# R1 — หนังเปิดหน้าแรก (เล่นตามการเลื่อน)

วันที่ 1 ตุลาคม 2026 · ส่วนแรกของงานออกแบบใหม่ (R1–R4) ตามที่ผู้ใช้ขอหลังดู UI ของ M3: หน้าแรกเปิดด้วยหนังแบบเลื่อนแล้วเล่น เล่าเรื่องเน็ตบ้าน/ไฟเบอร์/เครือข่ายทรู แล้วค่อยเข้าโปรและบริการ ใช้ prompt ของ MotionSites เป็นภาพอ้างอิงแนวทางเท่านั้น ไม่ใช้วิดีโอ ฟอนต์ stack หรือข้อความของมัน

## สิ่งที่ได้

- **หนังเปิดหน้า** (`src/components/site/home/FilmHero.tsx`, `FilmPlayer.tsx`, `film-timeline.ts`): ฉากเดียวค้างไว้เต็มจอ ขณะเลื่อนผ่านความยาว 150svh ต่อหนึ่งฉากข้อความ ภาพเดินตามการเลื่อนทั้งไปและกลับ ข้อความแต่ละฉากจางเข้า–ออกทีละฉาก ไม่ซ้อนกัน
  1. เหนือทะเลเมฆ ฟ้าสว่าง: หัวเรื่องหลัก (H1) สีกรมท่าทางซ้าย
  2. ใต้เมฆ เมืองกลางคืนมีเส้นไฟเบอร์แดง/ขาว: ข้อความสีขาวกลางจอ
  3. ลงตามสายเข้าบ้าน ทะลุหน้าต่างเข้าห้องนั่งเล่นที่มีวงคลื่น Wi-Fi: ข้อความสีขาวทางซ้าย
- **แถบปุ่มอยู่บนจอตลอดหนัง**: ปุ่มหลัก/ปุ่มรอง ข้อความ "รับเรื่องจากทุกจังหวัด…" ปุ่มเลือกฉาก ปุ่มข้ามหนัง และคำกำกับ "ภาพประกอบ ไม่ใช่ภาพเครือข่ายจริง" แถบเป็นกระจกขาวบนภาพสว่าง และกระจกกรมท่าบนภาพมืด
- **Header กระจกฝ้า** ทุกหน้า หนังวิ่งอยู่ใต้ header ในหน้าแรก
- **ส่วนอุปกรณ์ Wi-Fi** (`EquipmentSection.tsx`): ภาพ Router 3D/poster เดิมย้ายจาก hero มาอยู่ส่วนของตัวเองพร้อมจุดเด่น 3 ข้อ ยังคงข้อกำหนด "ภาพ True Wi-Fi Router ที่เด่น" ลำดับหน้าใหม่: หนัง → แพ็กเกจเด่น → เลือกบริการ → อุปกรณ์ → มือถือ → ขั้นตอน → โซลาร์ → FAQ
- **สีและตัวอักษร**: ink เป็นกรมท่า `#0e1630`, สีรอง (glow) ม่วง `#5b3fd1` แก้ได้และตรวจ contrast เหมือนสีอื่น, หัวเรื่องใช้ Anuphan

## ทำงานอย่างไร

- Server render เป็น**แผงเรียงทีละฉาก** แต่ละแผงมีภาพนิ่งจากหนังของฉากนั้น นี่คือสิ่งที่เห็นเมื่อไม่มี JavaScript, เมื่อเลือกลดการเคลื่อนไหว (reduced motion) และใน Mirror Editor ทุกข้อความอ่านและคลิกแก้ได้
- `FilmPlayer` (client) ตั้ง `data-film-live` เพื่อเปลี่ยนเป็น layout หนัง ทั้งสอง layout สูงเท่ากัน (จำนวนฉาก × 150svh) เนื้อหาด้านล่างจึงไม่กระโดด
- เฟรมโหลดหลังหน้าโหลดเสร็จ (`load` + idle): ภาพนิ่งของแต่ละฉากก่อน แล้วโหลดทั้งเรื่องแบบหยาบไปละเอียด (`loadOrder`) ครั้งละ 4 ไฟล์ ถอดรหัสด้วย `createImageBitmap` เก็บไว้ใกล้ตำแหน่งปัจจุบัน 12 เฟรม + ภาพนิ่ง ที่เหลือปล่อยหน่วยความจำ วาดบน canvas แบบเกลี่ยระหว่างสองเฟรมให้ภาพลื่น
- มือถือแนวตั้ง (`max-aspect-ratio: 4/5`) ใช้ชุดเฟรมแนวตั้ง โพสเตอร์ใช้ `<picture>` ตามกติกาเดียวกัน
- Save-Data หรือเน็ต 2G/3G: โหลดเฉพาะภาพนิ่งของแต่ละฉากแล้วเกลี่ยภาพระหว่างฉาก
- หยุดวาดเมื่อหนังพ้นจอ เปลี่ยน reduced motion ระหว่างใช้งานก็สลับ layout ทันที

## เนื้อหาที่แก้ได้ (schema รุ่น 2)

- `pages.home.hero`: `film` (รูปในคลังสื่อ ถ้ามี `sequence` จะเล่นเป็นหนัง ถ้าไม่มีจะเป็นภาพนิ่งเบื้องหลัง), `filmNote`, `beats` 1–4 ฉาก (หัวเรื่อง, เนื้อหา, ตำแหน่งข้อความ ซ้าย/กลาง/ขวา, สีตัวอักษร เข้ม/ขาว), ปุ่มหลัก/รอง, ข้อความเล็ก
- `pages.home.equipment`: หัวเรื่อง คำอธิบาย จุดเด่น 0–4 ข้อ ภาพ Router และคำบรรยายใต้ภาพ
- `media.<id>.sequence`: `{ landscape, portrait? }` แต่ละชุดมี `path`, `format` (avif/webp), `frames`, `width`, `height` — สคริปต์เขียนให้ หลังบ้านไม่ให้แก้
- `site.ui.filmScenes`, `site.ui.filmSkip`: ชื่อปุ่มสำหรับโปรแกรมอ่านหน้าจอ
- `CONTENT_SCHEMA_VERSION` เป็น 2 ร่างที่บันทึกด้วยรุ่น 1 จะแสดงเป็นปัญหาให้ทิ้ง (ยังไม่มีร่างจริงเพราะเจ้าของยังไม่ apply migration ของ M3)

## หนังชั่วคราว และการเปลี่ยนเป็นวิดีโอจาก Google Flow

ตอนนี้ใช้หนังที่วาดด้วยโค้ด `film-home-placeholder` (`scripts/media/film-placeholder.mjs` + `film-placeholder/scene.js`, ชนิด `illustration`) 120 เฟรมต่อแนว AVIF: แนวนอน 1600×900 ราว 2.7 MB, แนวตั้ง 720×1280 ราว 1.7 MB ผู้ชมโหลดเพียงแนวเดียว

วิดีโอจริงทำตามบรีฟใน Google Drive ของเจ้าของ: โฟลเดอร์ "Telemart Ubon - งานภาพเว็บ (Google Flow)" เอกสาร "บรีฟงานภาพและวิดีโอ เว็บ Telemart Ubon (Google Flow)" และส่งไฟล์ในโฟลเดอร์ย่อย "ส่งไฟล์ที่นี่"

- ภาพหลัก K1–K4 (16:9) ก่อน แล้ววิดีโอ C1–C3 ช่วงละ 8 วินาทีแบบกำหนดภาพเริ่ม/ภาพจบ (K1→K2, K2→K3, K3→K4) รอยต่อจึงตรงกัน
- ภาพประกอบ S1–S8 สำหรับการ์ดโปร หน้าแพ็กเกจ และแถบติดต่อ (ใช้ใน R2–R3)
- ห้ามโลโก้/ตัวอักษร/ลายน้ำ ภาพ AI เป็นภาพประกอบเท่านั้น ไม่แทนรูปสินค้า รูปอุปกรณ์จริงต้องมาจากทรูหรือ Telemart

เมื่อได้คลิป:

```bash
node scripts/media/film-frames.mjs --name home-v1 \
  --landscape C1-sky-to-city.mp4,C2-city-to-street.mp4,C3-street-to-home.mp4 \
  [--portrait C1-sky-to-city-9x16.mp4,C2-city-to-street-9x16.mp4,C3-street-to-home-9x16.mp4]
```

สคริปต์ต่อคลิปตามลำดับ รายงานรอยต่อ (ต่ำกว่า 4% = ต่อสนิท) เลือกเฟรมเท่ากัน 120 เฟรม บีบเป็น AVIF และพิมพ์รายการสื่อสำหรับ `src/content/media.ts` ถ้าไม่มีคลิปแนวตั้ง จะครอปกลางจากแนวนอน (`--focus` เลื่อนจุดครอป) ต้องมี ffmpeg ที่ถอด H.264 ได้ (`--ffmpeg` หรือ `FFMPEG_PATH`); ใน Claude Cloud ใช้ binary จาก `pip install imageio-ffmpeg` ได้ ทดสอบสคริปต์กับคลิป H.264 ที่สร้างจากหนังชั่วคราวแล้ว ได้เฟรมครบทั้งสองแนวและรายงานรอยต่อถูกต้อง

การดึงไฟล์จาก Drive: เครื่องมือ Drive ของ Claude ดาวน์โหลดไฟล์เป็น base64 ซึ่ง Claude Code บันทึกลงไฟล์เมื่อใหญ่ ทดสอบแล้วกับ PDF ~200 KB ส่วน `drive.google.com` ถูก network policy บล็อก ยังไม่ได้ทดสอบกับวิดีโอขนาดจริง (5–15 MB) ถ้าเครื่องมือ Drive จำกัดขนาด ให้ส่งคลิปทางอื่น

## ข้อจำกัดและงานต่อ

- หนังชั่วคราวเป็นภาพวาดเชิงกราฟิก ไม่ใช่ภาพถ่าย ใช้จนกว่าวิดีโอจาก Flow ผ่านการตรวจ
- ยังไม่ได้ทดสอบบน Safari iPhone/Chrome Android เครื่องจริง (ทดสอบใน Chromium headless ทั้งขนาด desktop และ Pixel 7)
- ไฟล์เฟรมอยู่ใน `public/` ใน repository ระหว่างพัฒนา เมื่อมีการอัปโหลดสื่อ (M4/R4) ควรย้ายไป Supabase Storage หรือ CDN และตั้ง cache ยาวด้วยชื่อโฟลเดอร์ที่มีรุ่น (`home-v1`, `home-v2`)
- ใน Mirror Editor หนังแสดงเป็นแผงนิ่ง (ดูทุกฉากและคลิกแก้ได้) ส่วนการเล่นจริงดูได้ในโหมดดูหน้าเว็บหรือหน้า public
- schema รับ 1–4 ฉาก แต่ editor ยังเพิ่ม/ลบฉากไม่ได้ (รายการแบบวัตถุคงจำนวนตามข้อตกลง M3) จะเปิดใน R4 พร้อม CRUD
- R2 (โปรแนะนำแบบแท็บและการ์ดมีรูป), R3 (หน้าแพ็กเกจกรอง/เรียง/เทียบ), R4 (CRUD สินค้าและบริการ + อัปโหลดสื่อ) ยังไม่เริ่ม
